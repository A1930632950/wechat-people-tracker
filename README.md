# wechat-people-tracker · 微信人物事件追踪

一个运行在 WorkBuddy 上的个人社交信息管理 Skill：把零散的微信聊天记录，变成**可持续更新的人物档案 + 事件时间线 + 待跟进清单**。

## 一、解决什么问题

跟人聊完天，过阵子就忘了对方这段时间干了什么；等想起某个人，翻聊天记录翻得头疼，手动整理每个人的近况更是麻烦。

本项目把这个过程自动化：你只需粘贴聊天记录，Skill 负责识别"谁、在什么时候、发生了什么值得长期记住的事"，增量更新到每个人的档案里。之后你随时可以问"张三最近怎么样""我多久没和李四聊了""下次和王五聊什么"。

它**不是聊天总结器**——只有具备长期检索价值的信息才会入档（人生变化、旅行考试面试、未来计划、关系变化、持续状态、对方偏好等），寒暄、表情、"哈哈哈哈"一律过滤。

## 二、主要功能

| 功能 | 说明 |
|---|---|
| 增量更新档案 | 每次上传判定为：新事件 / 旧事件补充 / 状态变化 / 重复，档案反映最新状态、历史保留 |
| 事件状态机 | 六态：计划中 → 进行中 → 已完成，及已取消 / 已改变 / 搁置；状态变化追加记录、可追溯 |
| 人物管理 | 人物 ID（PXXXX）唯一；昵称变更留痕；疑似同一人**永不自动合并**，须用户确认 |
| 溯源机制 | 原始聊天按批次（BXXXX）存档；每条事件带批次号 + 原文摘录（≤30字），记错了可回查 |
| 可信度分级 | 明确 / 计划 / 模糊 / 推断 四级，永不把推测当事实 |
| 更新前备份 | 每次写入档案前自动备份到 `data/backup/`，可整目录回滚 |
| 待跟进清单 | 未完结事项自动进入提醒单，支撑"下次聊什么"等查询 |
| 固定查询指令 | 近况查询 / 互动间隔 / 年度事件总结 / 全员近三月动态 / 聊天话题建议 |

## 三、安装方法

本项目当前为**本地开发状态**（Skill 本体 + 数据目录在同一个仓库）。

**在 WorkBuddy 中安装（用户级）：**

1. 将以下内容复制到用户级技能目录 `~/.workbuddy/skills/wechat-people-tracker/`：
   - `SKILL.md`（入口）
   - `references/`（extraction-rules.md / update-rules.md / person-rules.md）
   - `templates/`（person-profile.md / index.md / followups.md）
2. 数据目录**跟随项目**：档案数据读写项目根目录下的 `data/`（相对路径，迁移项目无需改配置）。首次使用若 `data/index.md`、`data/followups.md` 不存在，从 `templates/` 复制同名文件即可初始化。
3. 重启 WorkBuddy 会话后，说"更新聊天记录"即可触发。

**目录结构：**

```
wechat-skill/
├── README.md                        本文件
├── LICENSE                          MIT
├── .gitignore                       排除隐私数据与本地文件
├── SKILL.md                         Skill 入口（触发条件、固定指令、更新流程）
├── references/                      提取规则 / 更新规则 / 人物规则
├── templates/                       种子模板（person-profile / index / followups）
└── data/                            档案数据（含真实聊天记录，仅本地，不入仓库）
    ├── index.md                     人物总索引
    ├── people/                      每人一个档案 PXXXX-姓名.md
    ├── sources/                     每次上传的原始聊天存档 BXXXX.md
    ├── followups.md                 待跟进清单
    └── backup/                      更新前自动备份 BXXXX-<日期时间>/
```

## 三-1、隐私说明

本项目只把**代码与规则**发布到仓库，**真实数据一律不上传**：

- `.workbuddy/`：本地工作目录（记忆、脚本、个人上下文）→ 已被 `.gitignore` 排除
- `data/people/`、`data/sources/`、`data/backup/`、`data/index.md`、`data/followups.md`：真实人物档案与聊天原文 → 已被 `.gitignore` 排除
- 仓库内所有文件均使用相对路径或示例化人名，不含任何本地绝对路径、账号、凭据与真实个人信息

## 四、使用方法

**更新（粘贴聊天记录）**：把微信聊天复制粘贴发给 AI，并附四项元信息——聊天日期锚点、对方身份、视角指定（谁是我）、内容归属标记。格式见下方示例；缺项 AI 会先询问、不会猜测。

**查询**（自然语言即可）：

| 你说 | 得到 |
|---|---|
| "张三最近怎么样" | 该人物近期事件与当前状态 |
| "我多久没和张三聊了" | 依据批次存档计算距今天数 |
| "张三今年发生了什么" | 全年重要事件时间线 |
| "我下次和张三聊什么" | 基于待跟进清单给出话题建议 |
| "把所有人的近三个月更新给我" | 全人物动态总表（A 版时间线） |

**纠错与裁定**：AI 判定有误时直接指出，会以"修订批次（如 B0001-R1）"形式更正，原判定在批次存档中划线留痕。

## 五、输入 / 输出示例

**输入（用户上传）：**

```
【更新】
对方：张三（首次提供昵称即可，之后可用人物ID）
时间：2026-10-01 至 10-03
我是：文本中"我："开头的都是我
——以下为聊天原文——
我：你面试那家怎么样了
张三：还在等结果，说这周出；对了，我十月底可能去北京出差
```

**输出 1 · 本次更新摘要：**

```
【本次更新摘要】批次 B0007 ｜ 锚点日期 2026-10-01~03 ｜ 人物 P0003 张三
- 新增事件 2 条：E0012 等待面试结果（进行中）／E0013 计划十月底去北京出差（计划中·模糊）
- 过滤丢弃：约 5 条寒暄/表情
- 存疑 0 条
- 备份：data/backup/B0007-20261005-0930/（2 个文件）
```

**输出 2 · 人物档案事件表（写入 `data/people/P0003-张三.md`）：**

| 事件ID | 时间 | 事件 | 类型 | 状态 | 重要程度 | 可信度 | 来源 | 更新时间 | 备注 |
|---|---|---|---|---|---|---|---|---|---|
| E0013 | 2026-10 底 | 计划去北京出差 | 工作 | 计划中 | 中 | 模糊 | B0007｜"十月底可能去北京出差" | 2026-10-05 | 是否确定待后续聊天确认 |

**输出 3 · 待跟进清单（写入 `data/followups.md`）：**

| 人物 | 事项 | 预计时间 | 状态 | 提醒时机 | 关联事件 |
|---|---|---|---|---|---|
| P0003 张三 | 面试结果 | 本周 | 待更新 | 下次聊天 | E0012 |
| P0003 张三 | 北京出差是否成行 | 10 月底 | 计划中 | 10 月中旬 | E0013 |
