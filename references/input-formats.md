# 输入格式判定与元信息抽取

本 skill 接受两类输入。**开工第一步永远是判定格式**——格式决定了哪些元信息必须问用户、哪些可以自动拿到。能自动拿到的，不要问。

## 一、两种格式对照

| | 格式 A · 手动粘贴 | 格式 B · 导出格式 |
|---|---|---|
| 外观 | 纯聊天文字，无发言人、无时间戳 | 每条消息固定「昵称 / 时间戳 / 内容」结构 |
| 来源 | 从聊天窗口选中复制粘贴 | 聊天记录导出工具生成的 `.md` / `.txt` / `.docx`，或"合并转发"后在 PC 端另存 |
| 发言人 | 无 | 每条消息自带 |
| 时间 | 无 | 精确到分钟，如 `2026年10月03日 22:08` |
| 可靠性 | 依赖用户标注 | 结构化字段，高 |
| 元信息 | 四项**全部**要问 | 日期/对方/归属自动；"谁是我"可能需问一次 |

## 二、格式识别（第一步，必须实际判定，不得凭印象）

**判定为格式 B**：文本中同时存在 ① 独立成行的昵称；② 紧随其后、独立成行的时间戳。

时间戳判定正则（家族）：

```
^\d{4}\s*[年\-/]\s*\d{1,2}\s*[月\-/]\s*\d{1,2}\s*日?\s+\d{1,2}:\d{2}
```

- **命中**（且样本 ≥3 条这样成对出现）→ 格式 B
- **未命中**，但存在 `我：` `A：` 之类人工标记或无标记 → 格式 A

> 判定不了就按格式 A 走（多问总比猜错好），并在更新摘要里说明判定的格式依据。

### 格式 B 的常见变体与处理

| 变体 | 处理 |
|---|---|
| 时间戳写法不同：`2026-10-03 22:08`、`2026/10/3 22:08`、`2026年10月3日 22:08` | 同一分支，正则放宽 |
| 12 小时制带 上午/下午/晚上 | 换算为 24 小时制后再入档 |
| 夹单独日期分隔行（如 `2026年10月3日 星期六`） | 视为日期分隔符，其后的消息沿用该日期 |
| 无空行（昵称/时间/内容连续三行） | 结构判定不变，按行序识别 |
| 系统消息（"对方撤回了一条消息""XXX 邀请 YYY 加入了群聊""你已添加了 XXX"） | 过滤，不入档、不建人物 |
| 消息内容本身多行或含空行 | 允许；边界靠"下一个发言人+时间戳对"界定（见下节） |

## 三、格式 B 的解析算法

不要按"固定三行一组"硬切——内容可能占多行，硬切会错位。正确做法：

1. 按行读取全文，得到行序列。
2. 逐行扫描，找「**发言人 + 时间戳**」相邻对：第 i 行不是时间戳、第 i+1 行是时间戳 → 第 i 行是发言人，第 i+1 行是时间。
3. **内容** = 时间戳行之后，到下一个「发言人 + 时间戳」对之前的全部行（保留多行与内部空行）。
4. 规范化输出消息列表：

```
[{序号, 发言人, 时间(YYYY-MM-DD HH:MM), 内容}]
```

5. 解析得到的**格式示例**（导出格式的典型形态，昵称均为示意）：

```
阿凯
2026年10月03日 22:08
今天学了好多桌游

小北
2026年10月03日 22:09
玩了什么呀
```

解析结果：`(阿凯, 2026-10-03 22:08, "今天学了好多桌游")`、`(小北, 2026-10-03 22:09, "玩了什么呀")`。

## 四、元信息抽取

| 元信息 | 格式 B | 格式 A |
|---|---|---|
| **日期锚点** | 自动：取全部时间戳的 min~max；同日即单日 | 必须由用户提供 |
| **对方身份** | 自动：全部发言人昵称去重 → 剔除"用户自身标识" → 余下即对方；≥3 人按群聊处理 | 必须由用户提供 |
| **视角（谁是我）** | 昵称命中 `data/index.md`「用户自身标识（我）」表 → 判为我 | 必须由用户指定（三选一，见 SKILL.md） |
| **内容归属** | 自动：每条消息的发言人明确 | 按标记；无标记按上下文推断并标注"归属存疑" |

### 首次遇到未知昵称：该问才问

- **1 个未知昵称 + 1 个已在"用户自身标识"表中的我方昵称** → 直接判为对方，正常建档，不打断用户。
- **完全判不了谁是谁**（发言人 ≥3 且昵称都不在索引中；或全是陌生昵称）→ **必须询问**，不得猜测。
- **弱匹配**（昵称近似、同音，疑似已有某人物）→ 禁止自动合并，按 `references/person-rules.md` 输出候选让用户确认。
- 用户指认"某昵称是我" → 把该昵称追加进 `data/index.md`「用户自身标识（我）」表，注明批次；**之后同类输入不再询问**。
- 用户说"这是我以前用的昵称" → 同样追加为新行，不覆盖旧行。

## 五、批次存档要求（两种格式一致）

存 `data/sources/BXXXX.md` 时，除原始文本外**必须同时写入**：

1. **元信息判定结果**：格式（A/B）及判定依据、日期锚点、发言人清单、视角判定依据。
2. **解析后的消息列表**（格式 B 才需要）：序号 / 发言人 / 时间 / 内容——便于日后复核抽取是否准确。
3. **过滤记录**：被判为不入档的候选及理由。

这样"AI 记错了"时可以从原文与解析结果两头回溯。
